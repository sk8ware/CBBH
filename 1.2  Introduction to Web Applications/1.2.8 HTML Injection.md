## 🧩 HTML Injection 

### 📚 ¿Qué es HTML Injection?

Consiste en **inyectar código HTML** no controlado en una aplicación web, permitiendo que el navegador **renderice** ese código malicioso.

➡️ Ocurre cuando:

- La aplicación **muestra datos ingresados por el usuario** sin filtrar.
    
- No se **valida** ni **saneado** (sanitize) el input.
    
- El input es insertado **directamente** en el DOM.
    

---

### 🛠️ ¿Cómo funciona?

El navegador procesa el input inyectado **como parte de la página**. Esto puede permitir:

- Incluir **formularios falsos** (phishing).
    
- Modificar el **aspecto** de la página (defacement).
    
- Insertar **publicidad maliciosa**.
    
- Base para un **XSS** si se inyecta código `<script>`.
    

✅ **Ejemplo de código vulnerable**:

```html
<script>
    function inputFunction() {
        var input = prompt("Please enter your name", "");
        if (input != null) {
            document.getElementById("output").innerHTML = "Your name is " + input;
        }
    }
</script>
```

🚨 **Input de prueba**:

```html
<style> body { background-image: url('https://malicious.site/bg.png'); } </style>
```

Resultado: Cambias el **fondo** de la página inyectando solo HTML.

---

### 🧠 ¿Por qué es peligroso?

- Puede **alterar** el contenido visual.
    
- Robar **credenciales** (creando un login falso).
    
- **Inyectar anuncios** o redirigir a páginas maliciosas.
    
- **Daño de reputación** (defacement público de sitios).
    

---

### 🛡️ ¿Cómo prevenir HTML Injection?

- **Escapar caracteres HTML** (`<`, `>`, `&`, `"`, `'`).
    
- **No confiar** en el input del usuario jamás.
    
- Validar con **white-lists**: permitir solo lo necesario.
    
- **Sanitizar** entrada: eliminar o codificar caracteres especiales.
    
- Usar métodos seguros como `textContent` en lugar de `innerHTML`.
    

> **Prohibido**: `element.innerHTML = userInput;`
> 
> **Seguro**: `element.textContent = userInput;`

---

### ⚡ Tip rápido:

Si puedes inyectar:

```html
<style> body { background: red; } </style>
```

¡Tienes HTML Injection! 😈

---

> 💡 **Conclusión**: HTML Injection es el primer paso para **XSS** o **phishing**. Evítalo **validando** y **sanitizando** todo input del usuario — **NUNCA** confíes en lo que envía el cliente.
