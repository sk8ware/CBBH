## 📚 Public Vulnerabilities 

Durante un pentest, si no encontramos exploits públicos, el siguiente paso es buscar vulnerabilidades conocidas en la aplicación, sus componentes o su infraestructura. Esto nos ayuda a priorizar posibles vectores de ataque basados en severidad.

---

### 📖 ¿Qué son las Public Vulnerabilities?

Son vulnerabilidades ya conocidas, documentadas y generalmente con una **CVE** (Common Vulnerabilities and Exposures). Muchas de ellas incluyen:

- Descripción del problema.
    
- Severidad mediante **CVSS**.
    
- Exploits públicos o PoCs (Proof of Concept) listos para pruebas.
    

> **🎯 Tip**: El primer paso es identificar la **versión** de la aplicación, ya sea por el código fuente, headers, comentarios, archivos visibles como `version.php`, etc.

### 🧮 Common Vulnerability Scoring System (CVSS)

Un estándar abierto para medir la gravedad de las vulnerabilidades. Ayuda a priorizar los parches y evaluar riesgos.

|CVSS v2|Severidad|Puntaje|
|---|---|---|
|Low|0.0 - 3.9||
|Medium|4.0 - 6.9||
|High|7.0 - 10.0||

|CVSS v3|Severidad|Puntaje|
|---|---|---|
|None|0.0||
|Low|0.1 - 3.9||
|Medium|4.0 - 6.9||
|High|7.0 - 8.9||
|Critical|9.0 - 10.0||

> **🔎 Pro Tip**: Usa las calculadoras interactivas de CVSS para experimentar:
> 
> - [CVSS v2 Calculator](https://nvd.nist.gov/vuln-metrics/cvss)
>     
> - [CVSS v3 Calculator](https://www.first.org/cvss/calculator/3.1)

### 🔥 Back-End Server Vulnerabilities

Además de las aplicaciones web, los servidores backend y bases de datos también son objetivos:

- **Web Server Vulnerabilities**: Ejemplo famoso → **ShellShock** (2014) afectando servidores **Apache** mediante manipulación de variables de entorno en Bash.
    
- **Database & Server Vulnerabilities**:
    
    - Son cruciales para **escalado interno** una vez que comprometes acceso inicial.
        
    - Se explotan usualmente **post-explotación** para escalar privilegios o moverse lateralmente en la red interna.
        

---

## 🚩 Resumen de Proceso

1. Identificar versión de la aplicación/webserver/plugin.
    
2. Buscar CVEs públicas y exploits.
    
3. Evaluar la severidad usando CVSS.
    
4. Intentar explotación controlada bajo scope de pentest.
    

> **⚡ Recuerda**: ¡Estas vulnerabilidades no sólo afectan la web app, sino toda su infraestructura!
