## 🔐 Sensitive Data Exposure 

### 📚 ¿Qué es Sensitive Data Exposure?

Se refiere a la **exposición de información sensible** en la **parte visible** (client-side) de una aplicación web, como:

- Código fuente HTML accesible.
    
- Comentarios de desarrollador olvidados.
    
- Archivos JS externos.
    
- Rutas ocultas o información de debug.
    

➡️ Aunque normalmente no compromete el **back end** directamente, puede poner en riesgo:

- **Usuarios** (por ataques client-side).
    
- **Administradores** (acceso no autorizado).
    
- **Datos confidenciales** (usuarios, contraseñas, tokens, rutas ocultas).
    
- **Infraestructura** (servidores, bases de datos).
    

---

### 🖥️ ¿Dónde ocurre?

- **Código fuente**: View Page Source (`Ctrl + U`) en navegador.
    
- **JS/CSS externos**: Archivos importados al navegador.
    
- **Comentarios** HTML o JS.
    

**Ejemplo de código vulnerable**:

```html
<form action="action_page.php" method="post">
    <!-- TODO: remove test credentials test:test -->
    <input type="text" required>
    <input type="password" required>
    <button type="submit">Login</button>
</form>
```

🚨 **Problema**: Credenciales en comentarios visibles por cualquier usuario.

---

### 🛠️ ¿Cómo identificar exposición de datos?

✅ Lo que debes revisar en auditorías:

- `Ctrl + U` para ver el **View Page Source**.
    
- Buscar:
    
    - Comentarios sospechosos `<!-- ... -->`.
        
    - Credenciales o tokens expuestos.
        
    - Variables JS con configuraciones sensibles.
        
    - Rutas ocultas, paneles admin, archivos `.env`, `.git`, etc.
        

✅ Herramientas de ayuda:

- **Burp Suite** (Proxy / Spider).
    
- **Google Dorking** (`site:target.com filetype:env`).
    
- **FFUF / Dirbuster** para buscar rutas ocultas.
    

---

### 🔓 Impacto

- Acceso a **usuarios administrativos**.
    
- Descubrimiento de **rutas sensibles** o endpoints ocultos.
    
- Exposición de **API keys**, **tokens**, o **credenciales**.
    
- Recolección de información para ataques más avanzados (**pivoting** o **privilege escalation**).
    

---

### 🛡️ ¿Cómo prevenirlo?

- **Eliminar** comentarios innecesarios antes de publicar.
    
- **Minificar** o **ofuscar** archivos JS/CSS.
    
- **Clasificar** información: nunca poner datos sensibles en el cliente.
    
- **Validaciones** fuertes y restricciones server-side.
    
- **Obfuscation** de JavaScript para dificultar la lectura.
    

> **Regla de oro**: El navegador del usuario nunca debe recibir información que no quieres que vea.

---

### ⚡ Tip rápido:

Si encuentras algo como:

```html
<!-- API_KEY: 12345 -->
```

🚨 **ES UN HALLAZGO IMPORTANTE**: potencial para escalar acceso o robar datos.

---

> 💡 **Conclusión**: Revisar el código fuente de una página es un paso **crítico** en un pentest web. Una simple exposición puede derivar en el compromiso total de un sistema.
