## 🧹 Filtrado de Resultados en `ffuf`

Hasta ahora, `ffuf` filtraba automáticamente los resultados más irrelevantes, como los que devuelven código 404. Sin embargo, cuando todos los intentos devuelven **código 200**, necesitamos una mejor estrategia de filtrado. Aquí es donde entra el filtrado por **tamaño de respuesta**, cantidad de palabras o líneas.

---

### 🛠️ Opciones de filtrado útiles

Comando para ver todas las opciones:

```bash
ffuf -h
```

Filtros más usados:

| Opción | Descripción                            |
| ------ | -------------------------------------- |
| `-fs`  | Filtra por tamaño de respuesta (bytes) |
| `-fw`  | Filtra por cantidad de palabras        |
| `-fl`  | Filtra por cantidad de líneas          |
| `-fc`  | Filtra por código HTTP                 |

---

### 🎯 Caso de uso: VHost Fuzzing con filtrado

Sabemos que todas las respuestas incorrectas devuelven un **tamaño de 900** bytes. Usamos `-fs 900` para ignorarlas.

```bash
ffuf -w /opt/useful/seclists/Discovery/DNS/subdomains-top1million-5000.txt:FUZZ \
-u http://academy.htb:PORT/ \
-H 'Host: FUZZ.academy.htb' \
-fs 900
```

---

### ✅ Resultado relevante

```bash
admin   [Status: 200, Size: 0, Words: 1, Lines: 1]
```

¡Listo! Se detectó un VHost válido: `admin.academy.htb`

🔧 **Recuerda:**  
Agrega el subdominio nuevo a tu `/etc/hosts` con:

```bash
echo "SERVER_IP  admin.academy.htb" | sudo tee -a /etc/hosts
```

Luego visita:

```
https://admin.academy.htb:PORT/
```

⚠️ Verás una página diferente a `academy.htb`, lo que confirma que son sitios virtuales separados en el mismo servidor.

---

### 📌 Siguiente paso recomendado

Lanzar un escaneo recursivo sobre el nuevo vhost para descubrir rutas ocultas:

```bash
ffuf -w /opt/useful/seclists/Discovery/Web-Content/directory-list-2.3-small.txt:FUZZ \
-u https://admin.academy.htb:PORT/FUZZ \
-recursion -recursion-depth 1 -v
```
