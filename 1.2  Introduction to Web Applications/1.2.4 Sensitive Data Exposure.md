## 🕵️ Sensitive Data Exposure 

### 📖 ¿Qué es Sensitive Data Exposure?

Se refiere a la **exposición de datos sensibles** (contraseñas, hashes, rutas, etc.) en la fuente visible de un sitio web — es decir, el **front end** accesible al cliente.

- Afecta al **cliente** (navegador) directamente, **no** al back end.
    
- Sin embargo, si se explota bien, puede dar acceso indirecto a:
    
    - Paneles de admin.
        
    - Directorios ocultos.
        
    - Credenciales válidas.
        
    - Rutas internas.
        
    - Información sensible de usuarios o del servidor.
        

---

### 👀 ¿Dónde buscar sensitive data?

- **Page Source**: `Ctrl + U` en el navegador o clic derecho → _View Page Source_.
    
- **JavaScript externo**: URLs que se importan al HTML.
    
- **Comentarios de código**: errores comunes como dejar credenciales de prueba.
    
- **Burp Suite** o **proxy web** para interceptar y analizar las respuestas.
    

#### 📦 Ejemplo de código vulnerable:

```html
<!-- TODO: remove test credentials test:test -->
```

> Las credenciales _test:test_ quedaron olvidadas en un comentario visible para cualquier usuario.

#### 🚩 ¿Qué más podríamos encontrar?

- Links ocultos.
    
- Directorios no públicos.
    
- Parámetros de debug.
    
- Funcionalidades no documentadas.
    

---

### 🛠️ ¿Cómo prevenir la exposición de datos?

- Eliminar **comentarios innecesarios** del código antes del despliegue.
    
- Limpiar el **código fuente** visible — que contenga sólo lo indispensable.
    
- Clasificar datos sensibles y limitar lo que se expone al cliente.
    
- **Obfuscación** de JavaScript o **minificación** para complicar la lectura.
    
- Usar herramientas de análisis para detectar exposiciones antes de producción.
    

---

### 🚩 Buenas Prácticas de Pentesting:

✅ Siempre revisar el _page source_ en los primeros pasos de un test.  
✅ Usar herramientas automáticas de análisis de código fuente (dirbuster, waybackurls, burpsuite passive scans).  
✅ Buscar en archivos `.js`, `.json`, `.xml` externos que cargue la página.

---

> 💡 Aunque parezca “sólo el front end”, **Sensitive Data Exposure** puede abrir caminos para comprometer el **back end** o la **infraestructura** entera.
