## 🌐 VHost Fuzzing con `ffuf`

En esta sección aprendimos cómo descubrir **subdominios internos o virtual hosts (VHosts)** que no tienen registros DNS públicos, utilizando el header `Host:` con `ffuf`.

---

### 🔎 ¿VHosts vs Sub-dominios?

- **Subdominios:** necesitan registro DNS público. Ej: `admin.hackthebox.com`
    
- **VHosts:** _no_ necesitan DNS público. Se accede mediante la misma IP, pero con diferente valor en la cabecera `Host:`.
    

⛔ Los subdominios ocultos o internos **no se encuentran** con técnicas normales de DNS fuzzing.  
✅ Pero sí pueden detectarse con **fuzzing del header Host** directamente contra la IP o dominio.

---

### 📁 Wordlist usada

Usamos la lista con subdominios comunes:

```
/opt/useful/seclists/Discovery/DNS/subdomains-top1million-5000.txt
```

---

### 🚀 Comando para descubrir VHosts

```bash
ffuf -w /opt/useful/seclists/Discovery/DNS/subdomains-top1million-5000.txt:FUZZ \
-u http://academy.htb:PORT/ \
-H 'Host: FUZZ.academy.htb'
```

---

### 🎯 ¿Qué hace este comando?

- Cambia dinámicamente el valor del header `Host:`
    
- Intenta acceder a subdominios internos como `admin.academy.htb`, `panel.academy.htb`, etc.
    
- Si alguno existe realmente como VHost, el servidor mostrará **una respuesta diferente** (por ejemplo, otro tamaño de contenido).
    

---

### ⚠️ Nota importante

A veces verás que **todos los intentos retornan 200 OK**, como:

```
webmail   [Status: 200, Size: 900, Words: 423, Lines: 56]
static    [Status: 200, Size: 900, Words: 423, Lines: 56]
```

👉 En estos casos, **debes fijarte en el tamaño de la respuesta**, ya que los VHosts válidos suelen devolver **una página distinta** (tamaño distinto).
