## 📥 Fuzzing de Parámetros POST con ffuf

En comparación con los parámetros **GET**, los **POST** no se pasan en la URL sino en el cuerpo de la petición. Esto significa que para identificarlos necesitamos modificar el **body** del request, y no la URL.

---

### 🔎 ¿Por qué fuzzear parámetros POST?

Parámetros ocultos en POST:

- No se muestran en la barra del navegador
    
- A menudo quedan fuera de validaciones de seguridad
    
- Son ideales para detectar:
    
    - Autenticación débil
        
    - Accesos por ID (IDOR)
        
    - Parámetros de lógica de negocio
        

---

### ⚙️ Comando de fuzzing con ffuf

Para fuzzear parámetros POST correctamente, usamos:

- `-X POST`: Define el método HTTP
    
- `-d 'FUZZ=valor'`: Inserta la palabra clave donde se prueban posibles parámetros
    
- `-H 'Content-Type: application/x-www-form-urlencoded'`: Requerido para backends PHP
    

```bash
ffuf -w /opt/useful/seclists/Discovery/Web-Content/burp-parameter-names.txt:FUZZ \
-u http://admin.academy.htb:PORT/admin/admin.php \
-X POST -d 'FUZZ=key' \
-H 'Content-Type: application/x-www-form-urlencoded' \
-fs 1234  # Sustituir por el tamaño que devuelve una respuesta vacía o sin éxito
```

---

### ✅ Ejemplo de resultado exitoso

```bash
id           [Status: 200, Size: 789, Words: 101, Lines: 9]
```

---

### 🧪 Verificando con curl

```bash
curl http://admin.academy.htb:PORT/admin/admin.php \
-X POST -d 'id=key' \
-H 'Content-Type: application/x-www-form-urlencoded'
```

📤 **Respuesta:**

```html
<div class='center'><p>Invalid id!</p></div>
```

Esto confirma que el parámetro `id` es **válido**, aunque el valor `key` no sea el correcto.
