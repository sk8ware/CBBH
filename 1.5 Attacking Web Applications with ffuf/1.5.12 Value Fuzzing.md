## 🔍 Fuzzing de Valores para Parámetros POST

Una vez identificado un parámetro válido como `id`, el siguiente paso es encontrar **valores aceptados o sensibles** que permitan acceder a información protegida (por ejemplo, una flag o datos de otro usuario).

---

### 🧠 ¿Por qué hacer value fuzzing?

- Algunos parámetros como `id`, `user`, `uid` o `page` pueden filtrar contenido dependiendo del valor.
    
- A menudo no están validados adecuadamente, y permiten acceso no autorizado (IDOR).
    
- Este tipo de fuzzing permite descubrir objetos accesibles secuencialmente o por patrón.
    

---

### 🧰 Generar wordlist personalizada

Podemos usar `seq` para generar un wordlist numérico (IDs del 1 al 1000):

```bash
for i in $(seq 1 1000); do echo $i >> ids.txt; done
```

---

### ⚙️ Comando ffuf para fuzzing de valores

Fuzzear `id=FUZZ` usando la wordlist generada:

```bash
ffuf -w ids.txt:FUZZ \
-u http://admin.academy.htb:PORT/admin/admin.php \
-X POST -d 'id=FUZZ' \
-H 'Content-Type: application/x-www-form-urlencoded' \
-fs 1234  # Sustituir por el tamaño de respuesta sin resultados
```

📝 Asegúrate de reemplazar `-fs` con el tamaño de las respuestas por defecto para filtrar resultados repetitivos.

---

### ✅ Validación con `curl`

Cuando `ffuf` encuentre un valor válido, puedes verificarlo con:

```bash
curl http://admin.academy.htb:PORT/admin/admin.php \
-X POST -d 'id=123' \
-H 'Content-Type: application/x-www-form-urlencoded'
```

💡 Si el valor es correcto, el servidor debería devolver la flag u otro contenido sensible.

---

### 🧪 Recomendaciones

- Fuzzear más allá de números (usa nombres, tokens, etc. según el parámetro).
    
- Para valores más complejos, genera wordlists con scripts de Python o descarga diccionarios de [SecLists](https://github.com/danielmiessler/SecLists).
    
- Siempre valida manualmente los hits más prometedores.
