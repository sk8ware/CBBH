## 🌐 Front End vs. Back End - Resumen Técnico

### 🧠 ¿Qué es Front End y Back End?

- **Front End**: Parte visible para el usuario (cliente).
    
- **Back End**: Lógica interna del sitio web (servidor).
    
- **Full Stack**: Desarrollo de ambas partes.
    

---

### 🖥️ Front End (Cliente)

> Todo lo que el usuario ve e interactúa directamente en el navegador.

#### 🔧 Tecnologías principales:

- **HTML**: Estructura del contenido.
    
- **CSS**: Estilos y diseño visual.
    
- **JavaScript**: Interactividad y lógica del lado cliente.
    

#### 🧩 Tareas relacionadas:

- Web Design (Diseño visual)
    
- UI Design (Diseño de interfaces)
    
- UX Design (Experiencia del usuario)
    

#### ⚠️ Problemas comunes:

- Si no se optimiza bien → sitio lento, errores visuales, mala experiencia en móviles.
    
- Depender demasiado del cliente puede generar fallos de seguridad.
    

#### 📌 Ejemplo simple de HTML:

```html
<p><strong>Welcome to Hack The Box Academy</strong></p>
<p><em>This is some italic text.</em></p>
<p><span style="color: #0000ff;">This is some blue text.</span></p>
```

---

### 🛠️ Back End (Servidor)

> Parte que procesa datos, lógica del sistema y conexiones con bases de datos.

#### 🧱 Componentes principales:

|Componente|Descripción|
|---|---|
|**Servidor Back End**|Hardware y sistema operativo (Linux, Windows, Docker).|
|**Servidor Web**|Maneja solicitudes HTTP (Apache, NGINX, IIS).|
|**Base de Datos**|Maneja datos persistentes (MySQL, MSSQL, MongoDB, etc).|
|**Frameworks**|Herramientas para desarrollar la lógica (Django, Laravel, Express, etc).|

#### 🧪 Funciones clave:

- Procesamiento de peticiones del cliente.
    
- Validación de datos.
    
- Lógica de negocio.
    
- APIs REST/JSON.
    
- Integración con servicios en la nube o externos.
    

#### 📦 Aislamiento seguro:

- Uso de **contenedores (Docker)** para separar lógica, base de datos y servicios.
    
- Mejora la seguridad y escalabilidad.
    

---

### 🔐 Seguridad en Front End y Back End

#### 🔍 Acceso al código:

- **Front End**: Código visible → se puede hacer **Whitebox Pentesting**.
    
- **Back End**: Código oculto → se hace **Blackbox Pentesting**, salvo excepciones como:
    
    - Código abierto (open source).
        
    - Vulnerabilidades como **LFI** permiten leer archivos internos.
        

#### ☠️ Ejemplos de vulnerabilidades:

- **SQL Injection**
    
- **Command Injection**
    
- **File Inclusion**
    

---

### ❌ Errores Comunes en Desarrollo Web (Top 20)

1. Permitir datos inválidos en la DB.
    
2. Foco excesivo en el sistema como un todo.
    
3. Implementar seguridad propia sin estándares.
    
4. Dejar la seguridad para el final.
    
5. Almacenar contraseñas en texto plano.
    
6. Crear contraseñas débiles.
    
7. No cifrar información sensible.
    
8. Depender en exceso del cliente.
    
9. Optimismo ciego (no considerar amenazas).
    
10. Usar variables directamente en URL.
    
11. Confiar en código de terceros.
    
12. Backdoors codificados.
    
13. SQLi no verificados.
    
14. Inclusiones remotas inseguras.
    
15. Manejo débil de datos.
    
16. Mal uso de criptografía.
    
17. Criptografía no segura.
    
18. Ignorar el factor humano (capa 8).
    
19. No auditar acciones del usuario.
    
20. Mala configuración del WAF.
    

---

### 🛡️ OWASP Top 10 (Vulnerabilidades más comunes)

1. **Broken Access Control**
    
2. **Cryptographic Failures**
    
3. **Injection**
    
4. **Insecure Design**
    
5. **Security Misconfiguration**
    
6. **Vulnerable & Outdated Components**
    
7. **Identification & Auth Failures**
    
8. **Software/Data Integrity Failures**
    
9. **Logging & Monitoring Failures**
    
10. **SSRF (Server-Side Request Forgery)**
    

---

> 💡 Como pentesters debemos identificar, explotar y explicar estas fallas. Son la base de la mayoría de ataques en aplicaciones web y sistemas modernos.
